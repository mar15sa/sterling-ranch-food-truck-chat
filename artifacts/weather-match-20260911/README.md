# Weather mockup fidelity and production release

Owner request: make the implemented weather component match the approved mockup, thoroughly verify it, release to production, and change the image based on the weather. This explicitly approves the visual correction and production release.

Root cause: the earlier implementation paired a generic striped SVG with an unrelated landscape, used a tall empty composition, and then reused scene crops as small symbols. These did not reproduce the approved organic engraving or compact hierarchy. The replacement uses ten complete engraved weather scenes plus a separate matching symbol sheet, keeping typography and spacing aligned with the mockup.

Before: a floating geometric symbol above a static landscape, large empty gaps, and symbols that looked unlike the mockup. After: sun/clouds and the landscape are one illustration; clear, partly cloudy, overcast, rain, winter precipitation, storms, fog, wind, clear night, and cloudy night select different images. Each outlook also selects its own engraved symbol. Unknown conditions retain their source wording and use neutral art. Missing images do not remove forecast text. Failures replace outdated conditions with an unavailable message and keep the official forecast link.

Data authority remains the existing NWS service for ZIP 80125; no fixed forecast values are embedded in the application. Server source freshness and coordinates are unchanged. Shared presentation chooses a local allowlisted image from forecast wording and the day/night field. It does not change source authority or any Community Assistant behavior. Forecast image selection refreshes at the end of a forecast period, every 15 minutes while visible, when returning to the page, and after a failed request. Automated Assistant requests, if the existing release monitor submits them, explicitly use isTest=true.

Validation covers six viewport sizes, 31 condition/day-night cases, all ten weather images plus neutral fallback, all small-symbol positions, absence of weather data, HTTP failure, missing artwork, absent wind/precipitation, zero precipitation, long descriptions, and time-driven day-to-night refresh. Browser WCAG AA checks, visual inspection beside the approved mockup, shared-page smoke checks, the project quality gate, the live staging monitor, and exact staging/production deployment revisions provide release evidence.

The weather art is generated with the built-in image_gen tool. Full prompts are in prompts.json; source filenames and optimized sizes are in asset-manifest.json. Production assets live in public/weather-art/. Each scene is an optimized 600×450 WebP; the symbol sheet is a 1000×400 WebP. The original generated files remain untouched. build-assets.cjs performs only size/format optimization.
