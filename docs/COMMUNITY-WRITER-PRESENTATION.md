# Writer evidence presentation repair

Preimplementation plan, September 14 Denver / September 15 UTC. Local experimental candidate only; no production configuration, source approvals or UI changes.

Root causes established by the preceding evidence-selection replay:

1. Normalized live-source JSON places an internal `scopeLimit` sentence beside extracted facts. Both writers attributed the limitation to the official website. A statement that this adapter does not establish menu details is not proof that the website lacks a menu.
2. The writer receives UTC check times but no consistent community-local display context. Haiku presented a UTC clock time without its timezone in both pool answers.
3. The strict writer tool schema embeds per-packet action IDs. Three first uses of distinct schemas took roughly ten seconds; reuse took roughly two to four seconds. Provider documentation confirms schema-compilation overhead, but this timing association has not isolated causality. [Anthropic documentation](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), checked September 15 UTC.

Implement independently selectable presentation options so each can be compared without changing the other: (a) separate evidence facts from assistant-side coverage and observation context; (b) use a stable strict output schema with action IDs supplied in the message inventory and checked exactly in software. Keep the existing presentation as the experimental control. No new model calls are required for implementation and offline checks.

For the first option, require the profile's valid timezone and the evaluation clock. Move only the known metadata fields from the exact identity-matched live projection into a separate assistant-context inventory, preserving requested dates/filters, actual events/status/trucks/collection dates and scoped match outcomes. Format observation/check times with their local timezone; keep UTC values for audit. Do not rewrite raw source records, hashes, approvals, roles, provenance, facts, or actions. Governing/static evidence and qualifications remain byte-identical. If a live projection's text and stored scope disagree, reject the transformation instead of presenting altered facts. A community/timezone mismatch must fail, not guess. Source failure diagnostics remain intact.

For the second option, keep strict structural output and the existing answer/action fields, but use one source-independent string-array schema for action IDs. The message still contains the exact approved action inventory. Existing software rejects unknown/duplicate action IDs and unverified URLs; packet checks reject changed versions and cross-community identities before and after generation. The stable schema cannot authorize a link. A later model comparison must count new invalid-action outputs and both initial and repeated latency.

Resident before/after if proven: honest descriptions of what the assistant could verify, correctly labeled local timestamps when useful, and fewer repeated schema setup delays. This is a shared presentation boundary for all supported connector families and profiles, not a food/pool phrase patch. Profiles retain timezone and source configuration; adapters retain fact and capability authority. No source refresh or healthy-empty behavior is altered.

Required offline tests: actual calendar/status and extra live bridge projections; two profiles/timezones including date rollover and daylight-saving offsets; full metadata/fact conservation; no source/action mutation; conflicting source preservation; exact rule exceptions; malformed/mismatched projection rejection; unavailable source diagnostics; stable schema identity across zero/one/many action inventories; unknown/duplicate/invented link rejection; evidence expiry after composition; full candidate composition/check/repair request consistency. Historical replays must retain their captured clock and remain explicitly historical. Add a saved-input audit of the previous selected writer packets without provider calls.

Release evidence remains outstanding: independent repeated model/full-answer comparison, broader family tests, calibrated semantic assessment, actual total cost and p95, owner review and authorized release. No resident diagram change is required for this optional experimental path. Notion synchronization remains pending under the prior external-write rejection; save the precise decision/audit update locally.

## Implemented and verified locally

Implementation revision `daf8921`: `writer-presentation.js` adds independently selectable context separation and stable action schema. `runCandidate` accepts optional `writerPresentation`, applies it to initial writing and repairs, and gives its semantic checker the same separated facts/context. The default control remains unchanged; no resident route imports this experimental implementation. Source packet IDs, versions and text are preserved internally, and the existing source/expiry/action gates still decide whether a draft may proceed.

Forty-one focused tests passed with zero failures, skips or cancellations. Coverage includes transformed actual calendar/status/food/collection parser output, two configured communities, synthetic Denver/Tokyo timezones, local date rollover and winter/summer offsets; unknown/duplicate action and invented URL rejection; altered source and timezone mismatch rejection; rule/conflict preservation; consistent writer/checker/repair context; and expiration after writing. These prove input construction and failure handling, not real-model factual fidelity.

The saved-request audit passed on 64 transformations: sixteen historical writer inputs across two writer models and four known question families, each tested as unchanged control, separated context only, stable schema only, and combined. Each source's factual fields, static rule text/qualifications, actions, requested needs and existing source-gap diagnostics remained intact; the original packets were not mutated. Three distinct original schemas became one schema with the stable option. This is not 64 independent resident scenarios, a live answer test, or proof that first-use latency is removed.
