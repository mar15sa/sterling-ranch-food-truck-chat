# Evidence selection diagnostic

Preimplementation plan, September 14, 2026. Status: proposed local experiment; no resident integration, model selection or release.

Root cause: candidate retrieval returns up to four rules for each non-live factual/process need regardless of whether a rule can answer it, and appends all 25 approved static catalog entries. The saved food-menu and pool-hours writer inputs each contain 30 sources, including billing, mailbox and private-building material. Governing sources can also contain useful process instructions, so excluding every rule from non-permission questions would lose necessary evidence. A shared semantic relevance decision must preserve both the requested subject and the authority for each detail.

Proposed diagnostic: ask Haiku and Sonnet independently to select relevant source IDs from the same exact captured packets. Give the original question and prior resident messages, the interpreted needs as hypotheses, and complete approved source text/roles/scopes/actions. Never generate replacement evidence or rewrite excerpts. Preserve selected documents in full so exceptions and conflicting statements survive. Preserve all previously bound live sources and diagnostics automatically; this stage cannot decide that an unavailable feed proves no event. Retain actions only with their original selected source, label, URL, version and community. Invalid output means no usable selection, not silent pruning. Model selection is a relevance proposal, never source approval, completion, currentness or proof of absence.

Resident before/after if later proven: reduce irrelevant instructions and links while retaining all supported requested details and honest gaps. No fixed community facts, topic keywords or answer wording enter the shared selector. Profiles and adapters remain responsible for source identity, scope, live capabilities and freshness. An experiment is not a change to resident behavior.

Use four existing development cases: menu plus truck schedule, pool status plus regular hours, shed height plus application, and lighting approval process. These span changing operations, stable information, governing rules, forms and a process whose controlling requirements live in the rules. Test both eligible models twice on each exact packet (16 calls), randomized, without modifying interpretation, retrieved text or answer instructions. Capture every request, raw response, usage and elapsed time. Compare retained required evidence, obvious distractors, exceptions, conflict visibility and missing-source behavior separately from structural validity. These known cases are not a holdout or human calibration.

Reserve the complete design before any call, within the remaining $1.158288 of the current $5 phase (previously $3.841712 reserved, $1.441015 known cost). If the full design does not fit, stop before calls; do not drop trials to manufacture a result. Measure this added stage's cost and latency; smaller writer payloads alone do not prove a cheaper or faster full answer. No new subscriptions or paid embedding API.

Offline tests must cover two communities, exact source/action/version preservation, omitted live selections, wrong IDs, duplicate IDs, attempted text injection, malformed output, stale live packets, cross-community packets, empty selection and unchanged source-gap diagnostics. A known source conflict and a rule containing a process qualification must remain intact when selected. The selection algorithm must not receive previous assistant answers or held-out labels. Before any adoption, broader recall and repeated full-answer quality/cost must pass; a relevance model may itself miss evidence.

This diagnostic uses historical captured packets with their original evaluation clock only. It fetches no live evidence and must never label those packets current now.
