# Community Assistant friendly-neighbor voice

## Resident problem and root cause

The assistant protects residents from unsupported answers, but some safe answers still sound like a source database or a compliance report. The awkward wording comes from several shared paths: source-derived fallback prose, live event formatting, live pool-status presentation, generic evidence boundaries, and interface labels. These paths do not all use the grounded answer composer.

The affected family is every supported Community Assistant route, especially live events, current status, source outages, missing evidence, and a rejected or unavailable grounded rewrite.

## Behavior before and after

Before:

- Official clauses such as “install and energize” could reach a resident when grounded rewriting was unavailable.
- Events displayed machine dates such as `2026-09-11` and times such as `9:00 AM`.
- Pool answers repeated the internal CAB color label and the translated status.
- Safe evidence boundaries used phrases such as “connected official community sources.”
- Interface labels sounded like a verification report.

After:

- The grounded composer is explicitly asked to sound like a helpful neighbor and use ordinary verbs, contractions, natural dates, and complete next steps.
- The source-built rules fallback translates stable policy grammar without changing its dates, limits, requirements, or actions.
- Live events render their connector-provided dates and times in natural resident language.
- Pool answers show the profile-approved resident meaning while retaining the exact live status evidence behind the response.
- Missing-evidence and conflict paths use short, plain explanations.
- The interface keeps trust cues while using softer labels.

## Authority and reuse boundary

Routing, source selection, approval, freshness, conflict handling, and claim verification remain unchanged. Voice runs only after those decisions. No topic-specific answer, community fact, date, rule, fee, contact, or URL was added to shared application code.

The live pool meaning remains profile-owned. Event facts remain connector-owned. Core code only formats source-provided values and supplies source-independent presentation copy, so the behavior works for another configured CivicPlus community.

## Failure behavior and links

When grounded synthesis fails, the existing verified draft remains the factual source and receives only bounded grammar cleanup. When live evidence is unavailable, the response stays unverified and keeps only the configured official action. Voice changes cannot promote a source, add an action, or change answer status.

## Tests and release evidence

Family-level checks cover:

- unsupported named projects staying on the generic evidence boundary;
- nearby pool intents continuing to avoid the current-status connector;
- event answers preserving their event while using natural dates and times;
- pool answers preserving live authority without exposing the color code;
- holiday-light fallback prose preserving every date and cutoff;
- resident-literal protection rejecting new factual answer templates; and
- interface trust, uncertainty, action, and next-step labels.

The full local test suite and resident-literal guard must pass before review. Any hosted or staging questions must use test mode.
