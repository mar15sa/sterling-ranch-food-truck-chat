# Shared section context repair

Status: initial evidence repair implemented locally; not released. September 14, 2026.

Root cause: selected rule chunks lose neighboring requirements. The current decorator computes full text for an excerpt but retains the partial original text in the evidence passed to composition. Its existing full-text lookup also groups only by node ID, without a publishing-version check. The first diagnostic experiments establish missing fence options and missing lighting submission requirements as two examples of this shared mechanism.

Before: a selected section can stop immediately before its options, exceptions, or process steps. After: the composition evidence contains all available matching chunks within a bounded same-version section, with chunk identities and coverage metadata. This is not proof that the index contains every part of the official publication. This does not establish relevance or resolution by itself; shared interpretation, retrieval/reranking, composition, and semantic checking remain goal work.

Authority decision: start only from a unique exact match in the already loaded rules index. Require official URL, community identity, section/subsection boundary, and publishing product/job or parent-document/content-hash identity. Never expand owner-approved claim projections, pending/withheld evidence, stale/expired/superseded/future records, or mismatched versions. A per-query eligibility callback preserves existing source restrictions. Preserve the original source on uncertainty or when the complete section exceeds the budget; mark incomplete context rather than silently truncating it.

Reuse boundary: matching, ordering, bounded assembly, and diagnostics are shared code with no community names, rules, or facts. The existing index supplies evidence and version identifiers. Profile/connector authority contracts are unchanged. Official actions and live operational sources are unaffected.

Validation: synthetic multi-community/version/approval/size cases; real indexed fencing and lighting context recovery; unchanged original input; expired and withheld sibling behavior; existing rule, composition, authority, and source tests. Test questions remain marked as tests. Model selection and new recurring costs are not decided by this repair. Pre-release source revalidation, required gates, and exact live revision verification remain outstanding.

The final handoff to both AI writers previously cut text at 5,000 or 6,000 characters per source. It now budgets whole evidence units across sources (30,000 source-body characters). A larger unit may use its exact contained excerpt, or be explicitly marked omitted. This is a source-body allowance, not a cap on total request tokens: labels, actions, questions, instructions and existing labeled facts add overhead. Explicit question-specific rule projections remain projections. Repeated copies of the same expanded section are removed before writing. No model selection, subscription, timeout, production configuration or UI changes are included.

Checkpoint validation: the broad offline suite passed 830/830 before the final prompt-budget changes. The combined related-family rerun passed 65/65 after the final runtime edits, including intercepted provider requests that prove a trailing requirement beyond 6,000 characters reaches both writers and that approved projections remain restricted. The final log is artifacts/quality-eval/section-context-focused-final.log. The resident-fact literal guard and diff whitespace check passed. The broad run is not the final exact-candidate release gate. Existing source-built fence and lighting wording still needs composition work; recovered evidence alone is not a measured resident-quality win.

Regression found and corrected: deduplicating source entries in the decorator changed an ambiguous question's evidence confidence. Source entries now remain intact for answer decisions; only the writing-budget layer suppresses repeated full context. The related generic evidence-boundary test failed before that correction and passed after it. The failure log is retained separately as section-context-focused.log.

No additional paid model calls were made for this repair. The earlier matched two-scenario experiment remains preliminary context-cost evidence; complete current-versus-candidate costs and representative blind quality scoring are still required before selecting the final implementation.

Documentation: the local candidate image and accessible explanation were appended to [How the project works](https://www.notion.so/3dabf909186d8166b507c2a4e1d1aced) and the [guide hub](https://www.notion.so/3dabf909186d81789a09e4648dbb4bbe), then fetched to verify the text and image. Existing live-flow diagrams retain their dated status. This does not mark the candidate live.
