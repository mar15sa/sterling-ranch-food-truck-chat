## Costs and performance

Both comparisons used existing local vectors/models: zero paid API calls, subscriptions, new model files or deployments. In the hybrid follow-up, ten pure-semantic routing packets had median / sample p95 476.5 / 1,417 ms; hybrid routing had 2,332.5 / 6,410 ms. The latter leaves little room for planning, writing and checking under the proposed normal-answer p95 of ten seconds. These are desktop packet timings, not a complete-flow p95, and independent stage p95 values must not be summed.

Initialization: community 1,310 ms; rules 2,653 ms. Peak harness memory: 424,427,520 bytes (about 405 MiB). Production concurrency, hosting and finished-answer costs remain unknown. Source character totals are diagnostic context size, not paid token usage. No new model/provider commitment has been selected.

An additional local CPU profile of six preserved governing-rule queries is saved in artifacts/quality-eval/rules-keyword-profile-20260915. It confirms work in repeated replacement-document matching, tokenization, phrase normalization and search-statistics construction. The current hybrid adapter creates a fresh keyword-index object every query, defeating the rules function's object-keyed statistics cache. This is a concrete performance lead, not a proven optimization. Profiling adds overhead; raw query times are not production benchmarks. Any cache reuse must remain bound to the exact immutable source corpus and current per-question eligibility, with identical rankings and expiry/withdrawal behavior.
